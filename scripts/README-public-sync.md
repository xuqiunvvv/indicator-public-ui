# 公开版本生成与 GitHub 同步

固定目标：`xuqiunvvv/indicator-public-ui` 的 `main` 分支，生成文件置于 `public-site/`。该目录可作为其他托管平台的发布根目录，无管理后端运行依赖。仓库其他路径保留，已有网站不会因本程序调用而部署。

执行 `node scripts/sync-public-github.mjs`，从标准输入读取 JSON 设置：`managementToken`、`githubToken`、`commit`。也可由运行环境提供 `MANAGEMENT_SITE_TOKEN` 和 `GITHUB_TOKEN`，标准输入为 `{ "commit": true }`。默认仅校验，不提交。不要在命令参数、文件、日志或仓库中写凭据。

程序先对六范式查询 `/api/publications?domainId=...`，没有公开指针就跳过；再读取所指定的 `/api/archives/{archiveId}` 确认自身完整指标行存在，最后读取公开快照中的索引。缺失完整原始指标库、18个索引字段、参数数组、条数或编码不符时整轮停止。不调用无公开版本范式的 public-snapshot，避免旧管理接口的初始化副作用。

网页名称、分类、类型、单位、频率、实时能力、状态、别名、介绍、入参、出参与筛选符均由同一份索引生成，不使用原始公开明细中的旧出参覆盖。内部API信息、DS接口ID、发布者和维护来源记录不进入生成目录。参数字段采用白名单，未知字段先阻止同步、人工审核。

只接受全部范式通过后的一套完整发布。读取完成、上传前和分支更新前再次核对公开指针与策略。公开版本可以向旧普通版本回退，不以时间最大存档替代公开指针。数据与网页内容采用稳定哈希，运行时间不会产生空提交。GitHub Git Data API以一个提交更新整个目录，非强制推进分支，遇并发更新停止；旧范式的遗留文件仅在生成目录内清理。

未变化时不写GitHub；校验、上传、并发检查失败时不推进分支。上传中途失败可能留下不可见的未引用blob或commit对象，不会形成部分发布。分支更新已成功但回执丢失时，需要读取分支核实，不能将通信错误等同于未提交。

验证命令：`node --test tests/public-sync.test.mjs tests/public-site.test.mjs`。

目前没有配置每日任务或管理系统配置窗口，也没有部署 WorkBuddy/AgentOS。定时执行仍需要受支持的长期只读认证通道；浏览器登录成功不等于程序下载通道可用。管理API返回403时停止，不更改权限或绕过拦截。
